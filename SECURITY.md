# Security policy

## Security maintainer

[@naicud](https://github.com/naicud) is the repository owner and security maintainer for
[KevlarRedOps](https://github.com/totem-srl/kevlarredops).
Responsibilities and project attribution are documented in [MAINTAINERS.md](MAINTAINERS.md).

## Report a vulnerability privately

Use [GitHub private vulnerability reporting](https://github.com/totem-srl/kevlarredops/security/advisories/new)
for vulnerabilities in this repository. Sign in to GitHub and choose **Report a vulnerability**
from the repository's Security tab. Private vulnerability reporting is enabled for this repository.

Include the affected commit, component, reproduction steps in an environment you control,
expected and observed behavior, impact, and any proposed mitigation.
Redact secrets, credentials, personal data, and customer or engagement information.
Do not open a public issue containing an undisclosed vulnerability or sensitive reproduction data.

The maintainer reviews the report, coordinates a fix and disclosure with the reporter,
and uses a public advisory when appropriate. There is no guaranteed response deadline or paid bounty.
Ordinary bugs and feature requests can use [public issues](https://github.com/totem-srl/kevlarredops/issues).

## Maintenance scope

Security triage targets the current `main` branch. Include the exact commit in each report.
No long-term support window or security backport commitment is declared for older commits.
Upstream PentestCode/OpenCode releases and upstream registry packages have their own maintainers
and reporting policies; this policy applies to the Totem repository.

## Authorized research

Use isolated labs or systems for which you have explicit testing permission.
This policy provides a reporting process for KevlarRedOps; it does not authorize testing
third-party targets, providers, accounts, or production deployments.
